# Changelog

## v0.14.0 — 2026-11-04

- Tride 0.14.0 writes format 0.74 (0.13.x wrote 0.72): a `.trd` is now the scene description (`manifest.json`) and its `assets/`, with no `scene.gltf` copy of the scene inside. A file saved by this release needs Tride 0.14.0 or later on every player; an older editor or player refuses it with the "newer format" error that asks to update Tride (TrideKit 0.5.0 says instead that the file has no `scene.gltf`, and the web player 0.5 to 0.8 reports a parse error). glTF stays an import format: a tool that read `scene.gltf` out of a `.trd` finds none.
- Files saved by any earlier release, the oldest released form included, open in the editor and on every player and are converted as they open: their scene, maps, clips and skins are read once from the old file's glTF copy, and the editor saves them in the new form. What cannot be converted is listed as a problem and the rest of the scene opens. A skinned model saved by editor 0.11 to 0.13 lost its skeleton when it was saved; opening it now says so, and importing the source model again brings the skeleton back.
- A material keeps every glTF map: metallic-roughness, normal and occlusion join base colour and emission, each with its UV set and texture transform, and a map's placement and strength can be keyed and bound.
- A node keeps its rotation angles as they were typed (Y 400 stays 400) beside its quaternion: the editor shows them again after the file is reopened, and an axis without keys keeps that angle on every player while the other axes animate. Before, each player could pick other angles for the same pose, up to 180 degrees apart.
- Render settings that leave out tone mapping now draw in ACES Legacy on every player and in the editor, as a scene with no render settings already did; before, players drew such a scene in ACES while the editor drew it in ACES Legacy, so its whites differed. A scene that names its tone mapping looks the same as before.
- A camera whose near plane is 0 (as a glTF camera without znear reads), whose far plane is not past its near plane, or whose field of view or magnification is 0 now draws with the fallbacks iOS and Android take (near 0.1, far 1000) instead of handing Filament a lens it refuses; the same holds when an animated camera value writes such a number.
- The player builds every scene from the runtime's own description of it, as the iOS and Android players and the editor do: one way to draw on every platform, and skins of more than 256 joints are drawn. A scene drawn only in part says why once, as the scene problem `partialDraw`. Scene pictures are decoded in a worker, off the page's main thread.
- With dynamic resolution at medium quality or higher, the upscaled frame is sharpened with Filament's default sharpness 0.9, as on iOS and Android; before, the web did not sharpen it.
- An object of the scene file whose node material cannot be drawn (its compiled material is missing, out of date, or refused by the device) now draws its plain material, with its colours and pictures, and keys on it keep working; the runtime names the material once. A refusal by the device is reported as `material.package-refused`.
- A scene saved by an older version no longer keeps a copy of its glTF data in memory once it is open. The player's WASM no longer exports `ImportHandle`; older Tride files are still converted when they open.
- An orthographic camera now draws orthographic (before, the player drew it as a perspective camera) and fills the view at one uniform scale whatever the view's shape; a tap through it lands on what is shown.
- A scene whose parametric shapes animate costs less per frame: the player asks the runtime only for the shapes it rebuilt, and decodes the meshes of the scene file once per load instead of on every update. On a test scene in WebKit on an M3 Pro Mac, one update of the shapes took 0.4 ms instead of 0.8 ms. A datablock mesh's `materialParams` no longer carry the material's compiled record.
- Render overrides on a scene that sets no render settings keep the scene's own colour grading; before, any override switched the frame to ACES while it was on.
- A PNG the app hands to an image input that needs no turning or scaling keeps its exact colour where it is nearly transparent; before, the browser rounded those colours away.
- Up to five directional lights now light a scene; before, only the brightest one did, so scenes with several suns look different. The brightest casts the shadow and draws the sun disc, the next four light without shadows; a sixth and later sun is not drawn, and the runtime warns once about it, as it does when two suns are equally bright and either could take the shadow. On a test scene with several suns, a frame took 0.6 ms (4 %) longer in Chromium on an M3 Pro Mac.
- The player's Filament is 20.6 % smaller to download: it no longer carries the KTX2 (Basis Universal) and Draco decoders, which no scene reaches. `filament.wasm` goes from 3,403,555 to 2,607,797 bytes, and `filament.wasm` with `filament.js` from 1,065,492 to 845,807 bytes brotli-compressed. Compressed glTF content (KTX2 textures, Draco meshes) is not supported.
- A spot light saved without an inner cone angle draws with glTF's inner cone of 0, as iOS and Android draw it; before, the web drew it with a 30 degree inner cone, so its edge was harder.
