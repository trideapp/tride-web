# Changelog

## v0.16.0 — 2026-11-11

- Tride 0.16.0 writes format 0.76 (0.15.x wrote 0.75), which adds two interactions: a drag that turns a number input, and "Press ends". A scene that uses either needs Tride 0.16.0 or later on every player; Tride 0.15.x refuses it with the "newer format" error that asks to update Tride. Any other scene saved by 0.16.0 still opens on Tride 0.15.x, with a warning each time it loads that the file comes from a newer format and part of the scene may not show.
- Scenes saved by earlier Tride open in the editor and on every player as before, including files that carry a material's `uuid` or an animation clip's `gltfAnimationIndex`, keys the format no longer has: they are read and dropped. Open your scenes in Tride Editor 0.16.0 and save them once, and update the players that will open them before you hand the new files over.
- A scene file is read more strictly. A key that a camera, a light, a material, a material node, an animation clip or the node and mesh tables do not know is refused, and the message names the key and the list it is in; before, it was skipped and lost at the next save. Tride Editor does not write such keys: one comes from a script or a hand edit of `manifest.json`, so remove it there or make the change in the editor instead. A file that keeps its state machine at the top level of the manifest, a form from before each scene held its own, is refused with a message that says to open it in Tride 0.14.0 and save it.
- A transition between the states of a state machine (not of one of its layers) with a crossfade of 0 is instant again; before, it was read as a crossfade of 0.3 seconds.
- The runtime computes sines, cosines, powers, arctangents and the blend between two rotations with one portable maths library, so iOS, Android, the web and the editor give the same numbers bit for bit.
- Resetting a scene enters its state machine on the inputs' default values, as loading it does, and a machine whose first rule matches nothing enters its first state. Before, a reset could decide on the values it was about to clear and switch state once more on the next step.
- A Formula node with its own input pins can be wired straight into a scene input. Before, such a scene failed to load on every player with "unknown identifier" for a pin's name, and needed a Result node in between.
- An Unlit material whose Emission is a picture now shows that picture on an imported model; before, the mesh was drawn black. The picture is drawn by a compiled material that the editor adds on export, so export the scene again from Tride Editor 0.16.0. Until it is exported again, a scene from an earlier version draws as before and reports that it was saved by an older version of Tride. Not fixed yet: an Unlit material with an emission colour and no picture shows no glow on an imported model, and an Unlit material on a primitive is drawn lit. A fix comes in a later release.
- An older scene file whose glTF copy has a buffer cut short, or data that points past its buffer, now opens on the web, iOS and Android, as it already did in the editor: the players draw from the scene's own record and read none of that copy's buffers. Before, they refused the whole file. A file whose glTF copy does not parse, or that lacks the buffer's file altogether, is still refused.
- `TrideScene.beginFrames({ width, height })` opens a frame session for a page that records a scene frame by frame: `step(dt)` advances the scene and paints the frame in the same call every time, the first step after loading included, `await settled()` waits for pictures and material packages still on their way, `redraw()` paints the same state again, and `end()` puts the page's size, render settings and loop back. In a session dithering, temporal anti-aliasing and dynamic resolution are off, so two runs on one machine give the same frames; `setRenderOverrides({ temporalEffects: false })` does the same outside a session.
- The warning that glass does not refract is no longer printed for a mesh from the scene's file, whose glass does refract; it is still printed for glass on a primitive, a clone or a generated mesh, which draw it opaque.
- A handler of `onEvent`, `onStateChange` or `onInputChange` that throws no longer stops the scene: the throw is one problem for the page (`onProblem`, `tride-problem`), and the other handlers and the loop go on. Before, a throw from an event or state handler ended a running loop.
- A page can hear the scene's inputs change: `TrideScene.onInputChange(handler)`, or `<tride-scene observe-inputs>` with the `tride-input` event, reports after each tick every input whose value changed, with the value before and after. Computed inputs and the page's own writes are reported, triggers and pictures are not, and the scene compares its inputs only while someone listens.
- A node material whose package the browser's renderer refuses (a package for another Filament version, no WebGL shaders, a failed load) is now a problem with its own code, `material.package-renderer-refused`, once per material, through `onProblem` and the `tride-problem` event; without a handler it stays a console warning. If you ship scenes with node materials, handle it to know when a material is drawn plainly.
- A page with a strict Content-Security-Policy no longer has to allow `'unsafe-eval'`: the player runs no code built from a string. A page with no other restrictions needs `script-src 'self' 'wasm-unsafe-eval'; worker-src blob:`. The README lists what to add on a page that starts from `default-src 'none'` and for sound through `attachAudioMedia`. `worker-src blob:` is for the worker that decodes a scene's pictures; a later release will not need it. If your site serves its own copy of the `filament/` folder, copy this release's `filament.js` and `filament.wasm` before you take `'unsafe-eval'` out of the policy.
- The package now ships under the Tride Players Licence 1.2. It says in words what 1.1 already meant: your product may be open source, anyone who gets the player with it may build on it, build scripts may download the player from our releases, and your scenes are yours to publish under any licence. A product's source repository may also keep the player's files, unchanged and with the licence beside them.
- A load that the page's Content-Security-Policy ends now says what the policy refused. The error of `tride-error` on `<tride-scene>` and the rejection of `TrideScene.create` or `load` end with "The page's Content-Security-Policy refused", then each directive and the address it refused; a scene download the policy stops names `connect-src` and the scene's address, where it said only that the download did not start. `attachAudioMedia` no longer fails silently when the page refuses the sound tap's module: it rejects with a message that says what the policy must allow, and one problem at `audio.<input>` reaches `onProblem` and the `tride-problem` event. The notice that pictures are decoded on the main thread names `worker-src` when the policy refused the decoding worker.
- `TrideScene.setRenderSize(width, height, pixelsPerPoint?)` makes the drawing buffer exactly that many device pixels, whatever the canvas' CSS size, a CSS transform and the screen's density; `setRenderSize(null)` goes back to following the canvas. A size that is not a whole number of at least 1, or is above what the WebGL context draws, throws a `RangeError` and is never rounded. A canvas whose size the page wrote itself no longer draws the scene into a corner.
- Pictures handed over with `setImage` cost far less: the decoder is kept between pictures instead of being started for each one. A small PNG now takes about 1 ms of processor time instead of 18 to 22 ms, and a page streaming two such pictures 30 times a second used 0.20 of a processor core instead of 0.86 (measured in Chromium on an Apple M3 Pro). A long stream keeps a flat memory footprint, and a hidden page no longer slows the decoding and the upload of pictures.
- `setImagePixels(name, { width, height, data })` on `<tride-scene>` and `TrideScene` hands a picture to an image input as RGBA pixels, in the call and without a file: the input is loaded at once, and the first tick of 1/60 s or longer (or `tick(0)`) shows the picture; a loop faster than 60 Hz shows it a tick or two later. An `ImageData` from a 2D canvas fits as it is; a wrong call throws at once and changes nothing.
- `tick(dt)` and `renderNow()` now answer whether a frame was painted (`true` or `false`; before, nothing), and `renderNow({ neverSkip: true })` paints a frame the renderer would skip, so `tick(dt) || renderNow({ neverSkip: true })` advances a scene and paints it exactly once. `contextAttributes: { preserveDrawingBuffer: true }` in `TrideScene.create` keeps each frame on the canvas until the next one, so it can be read in a later task; without it, read a frame in the task that painted it.
